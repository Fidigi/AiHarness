# Web Application Architecture

> **Navigation:** See [`project-map.md`](../project-map.md) for repository boundaries and Docker validation.

## Overview

`@ai-harness/web` is a React/Vite client. Express remains authoritative for persisted sessions, workspaces, credentials, tools, and running agents; the browser owns drafts, bounded caches, preferences, viewport state, and declarative rendering.

HTTP and streaming contracts are defined in [`server-api.md`](./server-api.md). Session IDs, windows, dates, and reconciliation follow [`sessions.md`](./sessions.md).

## State Boundaries

| State | Authority and storage |
|---|---|
| Persisted sessions/messages | Server JSONL; browser keeps indexed windows only |
| `draft:*` conversation | Browser until first `POST /api/agent/runs` |
| Workspace cache | Per-tab `sessionStorage`, schema v2, 2 MiB and bounded entries |
| Sidebar organisation | Server `<data-dir>/sidebar-state.json`, opaque revisions; independent family pin/archive and ordered project names, never JSONL or browser storage |
| Workspace selection | `localStorage` key `ai-harness-workspaces-v1`, canonical current cwd and at most eight recent descriptors; no cached trust authority |
| Scroll restoration | Separate per-workspace map, 24 entries and 24-hour expiry |
| Preferences | `localStorage`, schema v4 with v1/v2/v3 migration, validated Enter or Mod+Enter send mode and cross-tab updates; separate `ai-harness-settings-navigation-v1` stores 17 whitelisted sections, optional same-category last-section choices for seven categories, fresh group/row IDs and five scope controls per exact canonical cwd/null, at most 24 contexts/65,536 code units, identifiers 4,096/cwd 8,192 code units; no configuration/drafts/trust/results |
| MCP detail selection | Separate `ai-harness-mcp-selection-v1` local preference; at most 24 canonical cwd/no-project contexts under 65,536 code units; workspace/scope/name only, never configuration, trust, Test or OAuth data |
| PTY tabs | Bounded per-tab v1 workspace metadata, never process/trust authority; Server owns processes and native UTF-8 byte replay; expired saved IDs require explicit replacement |
| Credentials | Provider secrets stay server-side; auth uses HttpOnly cookie or legacy per-tab bearer, never workspace cache/preferences |

The cache favors draft text over binary previews, strips provider keys, and discards/reconciles remote windows when the server revision changes.

Persisted Sidebar/search rows use real `SessionLink` anchors (`components/session-links.tsx`); drafts/actions remain buttons. `sessionLinkTo`/`projectLinkTo` encode only explicit identity/cwd/message fields, never copied auth/search/hash data. Ctrl/Cmd/middle/new-tab retain browser defaults; only unmodified plain activation closes mobile navigation. `Sidebar.onSessionContextMenu` receives the actual anchor event plus readonly sessionId/cwd/rendered href, without implicit API calls or default prevention. Explicit conversation/project tab actions use isolated native links. `services/navigation-base.ts` admits only a safe same-origin Vite base path into BrowserRouter; missing requested sessions remain unavailable rather than opening a different conversation. Preserve native anchor typography/contrast and the unchanged old visual controls.

`BrowserRouter useTransitions={false}` keeps location updates urgent alongside the synchronous Zustand workspace/session store. A canonical browser URL must not leave the previous React route epoch available for a file intent that a delayed navigation commit then retires. Keep the pane's complete workspace/cwd/session/navigation key and true-navigation cancellation; do not repair the writer by replaying across scopes.

## Durable Sidebar Organisation

Sidebar's **Organise navigation** disclosure exposes family selection (at most 100 unique families), bulk Pin/Unpin/Archive/Unarchive, Include archived, explicit Refresh and short-lived Undo. Fork rows share their family's checkbox/pin/archive state; clones do not. Pins sort first while preserving existing relative order. Archive does not delete or stop anything: the entire family stays visible when any loaded member is selected, needs attention or has a nonterminal run. Drafts always remain visible/local. Search and deep links still reach archived history. Terminal completed/failed/stopped runs alone do not force visibility; unread alone is not an attention request.

**Organise projects** supplies native project anchors, up/down buttons and bounded display-name edit/reset. Persisted project order/names precede this browser's current/recent workspace fallback; names never replace canonical cwd in URLs/operations. Plain project/session activation closes mobile navigation, while modifier/new-tab behavior remains native. Standard buttons, checkboxes, disclosure and form semantics support Tab/Space/Enter, the existing modal Escape/focus trap, and coarse-pointer targets. Selection resets on workspace or remote revision changes.

`hooks/useSidebarOrganisation.ts` reads when navigation is active, on window focus, every 15 seconds while visible and on explicit refresh. It does not write local storage. Revision checks refuse stale updates; conflict, undo expiry and uncertain transport reread canonically without replay. Busy/failed initial reads disable mutations, and navigation inactivity/unmount aborts transport and late publication without claiming rollback of an admitted write. Undo is offered only for the last acknowledged mutation and withdrawn on an observed foreign revision. An expired token produces explicit feedback, not success. State is shared by all authorized browsers of this server, not a new user-isolation boundary.

See [storage/API/limits](./server-api.md#independent-sidebar-organisation). Existing links/copies/search and unread/attention fixtures are retained; `components/sidebar-organisation.test.ts` adds family/run/archive predicates, and `e2e/sidebar-organisation-live.spec.ts` traverses the actual emitted Server and Web bundle with two browser contexts, journal-byte checks, keyboard/mobile navigation and Light/Dark desktop/mobile captures. These are native Chromium controls, not physical Safari/mobile certification.

## Detached Conversation Flow

```text
local draft -> effective configuration -> POST /api/agent/runs
  -> server persists user message and returns run/session IDs
  -> GET session state, then SSE events after last sequence
  -> temporary assistant delta keyed by messageId
  -> terminal/tool events trigger canonical session resync
```

`ChatView` may render one temporary streamed assistant message. Text/reasoning/checkpoint strings accumulate in refs; at most one pending animation frame publishes the latest projection, not one React/store update per delta. Terminal or retired views cannot publish that frame. Terminal events replace it with canonical history without duplicates, including when polling observes the matching settlement before SSE. Reconnection restores run queues, retries, partial text, pending extension interaction, and sequence position. A browser `online` event retires the existing subscription and performs a fresh canonical read/replay, rather than waiting for the 120-second transport idle bound; it never starts, retries or stops server work.

Durable transcript publication is separate from run/queue setter admission. `canSyncCanonicalSession` requires a private session-bound canonical witness, current collection generation/epoch/workspace/active-session identity and a nonstale sequence. Same-run SSE advancement may retire the setter without invalidating that transcript; known terminal recovery never reopens an absent run. Readiness resets/gaps trigger a fresh guarded GET because readiness contains no messages. A foreign `run.started` is only a discovery hint: its payload/version is not consumed, and fresh canonical state must independently name that exact run. Only the matching terminal settlement can pass an already-terminal event fence. If canonical discovery has already acknowledged its version, that exact terminal frame still requests one guarded final read, without replaying phase/notification effects; duplicate frames are deduplicated separately. Browser `online` renews state/SSE projection, never Core execution or prompt submission. Stream strings publish through one pending animation frame. Failed admitted state publishes the same stable error-notice ID as live failure, including when failure precedes subscription.

Session title metadata is presentation data, not SSE lifetime identity: a canonical title refresh must not restart ChatView’s subscription or discard a valid notice. The three existing attention/completion/failure Notification sites read the latest canonical title already in the store for the subscribed session at dispatch, with `AiHarness` for an absent/empty title. Full-address replacement and unmount withdraw owned transport; a title refresh does not create an address generation.

## History Edits and Live Settings

**Edit from here** stages a persisted user message in the current composer without a server mutation. A visible cancel control restores the previous draft and composer focus; navigation/reload discards the transient target. Only Send forks before that user entry and submits the replacement text on the new related session, preserving the source and excluding the old prompt. Staged input is literal conversation text, not a slash or shell command. **New chat from here** copies a persisted user entry even while its source run continues; neither source Stop nor active-leaf mutation is sent. Server refuses unwritten and running-command sources and locks in-session branch switching while busy.

Sidebar's lazy `SessionRowCopyMenu.tsx` captures the rendered saved row's session/entry/cwd/workspace primitives before awaiting, never a volatile reply or later current leaf. `session-row-copy-target.ts` refuses drafts, canonical children and unavailable scope; `services/session-row-copy.ts` sends only captured entry/scope to the fixed clone endpoint and checks independent provenance. Its native popover remains inside the Sidebar's modal/inert/focus owner. Route/session/workspace changes, unmount and mobile Sidebar inactivity retire pending transport/publication, including close/reopen with newer unsent composer intent. An already-admitted native copy remains persisted; withdrawal is not rollback. Native links/contextmenu and generic history actions remain separate.

Reasoning changes persist during streaming and apply at the next model request through Core's live host resolver. **Auto** clears the session override; the in-flight request retains its options and environment precedence remains authoritative.

Open the composer Model/Thinking scope disclosures to save the current model/provider or reasoning independently as a global new-session default. The save does not patch history, change a running request or enqueue a message. Project/environment overrides produce an explicit warning, including when a current session override hides them. Fresh drafts wait for their own effective configuration before sending and inherit its provider/model/thinking. Settings offers all seven reasoning levels plus inheritance, sends only dirty keys and disables saves when the settings read fails.

## History and Scroll

- Start with the latest bounded window and fetch older pages with `before`.
- Use `around` to materialize a search/deep-link target not currently loaded.
- Above the threshold, virtualize rows while preserving stable message anchors.
- Capture scroll state when scrolling, not from reused DOM during route cleanup. Explicit “Back to bottom” jumps reach the current tail synchronously, so a response arriving during a stale smooth target cannot leave the reader stranded above the tail; ordinary follow-tail behavior is unchanged.
- Debounce storage and correct measured offset after rematerializing an anchor.
- Keep full export server-side.
- The minimap is bounded by the flex message region rather than a fixed composer-height estimate; it cannot cover the composer or its Back-to-bottom control.
- Full workspace/session/address generations own pagination and deferred target scrolling. A late `before`/`around` page cannot publish after A/B/A navigation or change a replacement view's loading, focus or scroll intent. Scroll settling yields to user input and is disposed on replacement.
- Back to bottom occupies its own row at the top of the composer, including staged history edits and multiline input. It cannot float over transcript text, Cancel or other composer controls.

`MarkdownContent` keeps its native plain-text projection when the optional rich-reader import fails (including first-use offline). The failed import remains plain until an explicit page reload; no automatic reload discards a draft. Raw HTML stays non-executable. First service-worker installation claims the existing page without reloading; a later replacement still reloads once through the existing explicit update flow.

`e2e/conversation-live.spec.ts` uses emitted Server/static Web, real disk extensions and journals, and a deterministic loopback model endpoint. It covers offline/reconnect during model/tool/dialog/retry, canonical failure output, native history/search/fork/reload, held genuine stale pages, rich-reader asset refusal, native selection/focus, large-stream responsiveness and desktop/mobile Light/Dark captures. Service workers stay enabled. These are native Chromium contracts, not physical Safari/mobile certification.

## Workspace and Terminal Boundaries

Workspace hydration validates URL/saved candidates or requests the server default once. An invalid candidate may fall back only to a server-validated default. Failure withdraws the active descriptor, preserves saved choices and shows local EN/FR accessible recovery feedback instead of permanent Loading; newer selection supersedes stale replies. Persist canonical cwd only; Sidebar/recent labels use optional `displayPath`, tooltips and operations keep canonical paths, and the picker validates original input rather than a display label. Read the existing v1 selection cache under a 65,536-code-unit bound, filter metadata and discard cached trust/Git grants before fresh validation; this is separate from the v2 session-view cache.

Sidebar directory reads are sequence guarded and visibly report the server's 500-entry truncation. Its focus-trapped creation dialog submits one direct-child name and navigates into the server-returned canonical folder. A host-file-manager button appears only after the no-store availability probe succeeds; it submits only the current cwd. Dirty worktree removal sends `force: false`, then asks separately before the one explicit `force: true` retry.

A cwd change aborts stale requests, clears old file/search results, and keys React state so old PTY/file surfaces unmount before target state restores. Browser paths are never trusted directly: Server resolves them with `WorkspaceManager` and applies project trust before mutations or execution. Workspace descriptors keep resource-sensitive `trusted` separate from persisted-decision `operationTrusted`; Sidebar prompts, file/search surfaces and project configuration gates use the latter (with a compatibility fallback only when older descriptors omit it), so an implicitly safe empty folder cannot silently authorize an operation.

`WorkspacePanelBoundary` imports the real panel and original stylesheet together only at the workspace-eligible open-pane call site. Its key includes workspace ID/cwd, active session, navigation key and pathname/search/hash. Address fields also retire navigation when external history entries reuse the router's fallback key. Markdown file links capture their actual origin element and address before showing the pane; their next-task dispatch is suppressed after address change or origin disconnection, rather than publishing into an already replaced boundary. This is presentation lifetime, not file/trust authority. Local nonmodal loading/error exposes Close/Cancel without focus mutation or global suspension; failed imports stay rejected on reopen. Explicit page-reload retry warns about unsent text. A latest bounded file intent survives loading and the DOM/passive-listener gap; replay waits one task for the child's development StrictMode setup, is cancelled on teardown, and is superseded by newer live intent. Loading grants no new path/trust authority; see the bilingual [file-pane loading guide](../../users/en/workspace-loading.md).

`WorkspacePanel` retains tree/index, Git state/diffs, bounded uploads, file watching, and source/media/Markdown ownership. Eight metadata-only full-path file tabs retain source/preview/diff mode, keyboard navigation and close; selecting a tab rereads bytes. Pane/view/workspace/trust retirement clears tabs and aborts reads/watchers/uploads. `DocumentPreview.tsx` and `services/document-preview.ts` fetch only the authenticated fixed `/api/files/preview` route with streamed-byte/time bounds. Lazy `PdfPreview.tsx` owns a bounded PDF.js canvas worker with no active annotation/form/link/XFA layer; Server `api/docx-preview.ts` extracts only bounded inert main-document text. `delimited-preview.ts` renders bounded literal CSV/TSV tables without formula/HTML execution. Unsupported/oversized documents refuse preview without weakening download/trust policy. See the format/layout/authority contract for exact limits and exclusions. After explicit trust, Sidebar rereads the canonical descriptor so pre-trust omission of Git metadata does not remove worktree navigation. `TerminalPanel` dynamically loads xterm and the validated terminal stream service, resumes bounded ANSI output by UTF-8 byte offset, and stores bounded tab-ID metadata per workspace. Expired/interior/future cursors reset to retained event boundaries, not a serialized screen. Writes serialize under per-send/queued-byte/count limits; uncertain input retires the transport without replay. Clipboard paste uses xterm framing exactly once. Offline withdraws input; online renews SSE only. Workspace/trust/tab/panel retirement aborts owned transport, and saved-open restoration never silently replaces expired IDs. See the native terminal contract for limits, process/OS authority, installation evidence and UTF-8 replay bounds.

At desktop widths, the explorer region is portaled into the Sidebar below conversations, while the reader remains beside the main content. A hidden Sidebar or narrow viewport uses the combined fallback. Both presentations retain one `WorkspacePanel` owner: host/breakpoint changes may remount directory rows but preserve reader path/mode/bytes without rereading content. Options and upload use named, keyboard-operable groups with stable invokers; linked-directory modal ownership remains in its existing boundary. The maximized reader is a named modal using the shared focus/Escape machinery, not merely a wider CSS surface. Chat toolbar/composer controls wrap within the remaining column, with a bounded minimum model-input width; a wide viewport no longer implies a wide chat pane.

`App` owns workspace-terminal visibility and supplies its named launcher to `ChatView`. The 44px utility occupies normal composer-toolbar flow instead of floating over form controls; loading, unavailable-session and empty views retain it in their own flow. It is explicitly `type="button"`, never submits the prompt, and reuses the existing terminal request. File Options and shortcuts remain independent entry points.

On viewports at most 959 CSS pixels wide, an explicit `aih-open-terminal`/`aih-toggle-terminal` request retires the open file overlay before revealing the terminal. This uses the existing pane-retirement cleanup and does not rewrite the saved files-open preference, create a second PTY authority or alter desktop stacking. The real-PTY touch scenario in `e2e/terminal-controls.spec.ts` verifies explorer withdrawal before exercising the existing input/lifetime assertions; text in an occluded xterm DOM alone is not usable-browser evidence.

## Mobile Keyboard Layout

`hooks/useMobileKeyboard.ts` observes eleven fixed browser events with one coalesced animation frame. Compact chat needs editable focus, a coarse pointer, width ≤959 CSS pixels and height loss above max(160px, 20%) against a trusted unzoomed baseline; closing uses max(120px, 15%) hysteresis. Pinch-only loss, toolbar motion and panning do not open it. Focused rotation waits for blur before reseeding.

The view identity is a tuple of workspace ID/cwd, session ID and route key. Replacement scopes discard old publication and require fresh focus/input/composition intent. `hooks/mobileKeyboardStyles.ts` loads `hooks/mobile-keyboard.css` through a URL-only import; publication waits for readiness and a fresh measurement. Failed links are removed, stalled requests have an eight-second deadline, and a closed sample rearms retry. Disposal cancels the request, frame and listeners; success retains the link until its owner retires.

Secondary chat chrome collapses without replacing the composer, images, Queue or Stop. Compact primary actions retain the shared `--accent`/`--on-accent` roles rather than a separate fixed palette. Settings and MCP keep their own styles. Floating/overlay keyboards without viewport loss and initially zoomed/resized mounts may remain undetected; Chromium touch emulation is not physical Android/iOS/Safari certification. See the [mobile keyboard guide](../../users/en/mobile-keyboard.md).

## Rendering and Extensions

`themes.css` owns shared surface, text, border, action, status, syntax and command-ANSI roles for Light/Dark and the retained alternate themes; System resolves through preferences. Cache transcript notices use the shared primary text role without changing notice derivation, billing or transcript data. Independent terminal, generated-diagram and document content canvases retain their own rendering palettes.

An inert template provides bounded optional link metadata (65,536 code units, 1,024 nodes, 32 links); every failure/overflow preserves complete plaintext. Only the nearest contained menu/top nested or latest sibling dialog closes; a composer suggestion cannot dismiss a modal above it. Sidebar rename, linked loading, modal traps and the inline profile editor participate. A still-visible parent trap retains its original invoker while suspended by a child. Coarse pointers focus the dialog rather than an editable control and do not automatically return into inputs; ChatView also suppresses coarse mount autofocus. Settings returns to a safe invoker or the main region, never forcing a mobile editor. Explicit composer/edit/recall actions remain available; extension forms retain their stricter view/head/manual-edit guards. Touch emulation is not physical keyboard certification.
- `IconControlHints` mirrors existing translated names for icon-only controls on keyboard focus, with hover fallback where no native title exists. The visual copy is hidden from assistive technology, does not take focus or an Escape lease, follows scroll geometry and retires with hidden/inert/disconnected owners or changed names. No control value or draft is copied into navigation/persistence. Shared low-specificity pressed/disabled defaults preserve component states and larger targets.
- Child runs appear in `SubagentPanel`, the global monitor, and bounded notices.

Ordered extension presentation uses `ExtensionInteractionBoundary`: the real renderer and own stylesheet load only for a pending request. Local nonmodal loading/error keeps Close/Cancel, chat and Stop usable; rejection remains cached until explicit page reload with an unsent-text warning. Complete workspace/cwd/session/run/route identity retires stale transport and late presentation. Aborting transport suppresses browser publication, not an already accepted server response. Compatible same-ID/kind drafts and connected IME survive schema refresh; composition/legacy-229 Enter and Escape cannot acknowledge/cancel the form. Initial-focus admission observes intent even before import completes and again before first-frame focus. A replacement route presenting the same request is not fresh focus intent. Return is view/fallback/newer-focus/modal guarded; coarse pointers avoid unsolicited editable focus but permit guarded return after owned manual editing. The same mounted form advances between queue heads without intermediate restoration; editable intent belongs to the current head, not a previous head. This is not physical-device certification.

`session-store.ts` returns an explicit boolean admission receipt: accepted identical observations preserve callback authority, while stale replies are rejected. Session journal watermarks and run versions are separate. Exact same-version captured-head acknowledgement uses a private reply witness, not a generic membership exemption. App polling and Chat transport use full-address local lifetimes; bootstrap waits for canonical workspace id/cwd. Own-key access supports legal prototype-like session IDs. Negative retirement memory stays bounded (256 exact session records, 16 exact retired runs, conservative 1,024-bit filters); fresh privately witnessed current-state discovery may recover collisions. These are browser-local guards, not backend settlement, durable tombstones or a general fork-transaction guarantee.

## Common Changes

### Change chat or session state
Update API parsing, store hydration/windows, `ChatView`, detached protocol fixtures, reconnection/duplicate tests, and long-history behavior together. Preserve urgent router updates alongside external-store identity and the real-file/PTY assertions and security guard; metadata or timing changes must not retire a valid intent behind an already canonical URL.

### Change a visible surface
Update component and scoped CSS, keyboard/focus behavior, responsive layouts, axe coverage, and Docker-generated visual baselines.

### Change browser persistence
Version and validate the schema, add migration/fallback tests, preserve bounds and secret stripping, and test cross-workspace/cross-tab behavior.
