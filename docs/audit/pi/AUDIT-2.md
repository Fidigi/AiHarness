**Objective:** determine, at the pinned AiHarness commit, (1) the complete observable gap to Pi CLI `1.0.0`, and (2) every material implementation change required by the pinned Pi Web `0.9.3..0.10.0` delta. The audit evaluates behavior and contracts, not file-name or framework identity.

### Scope rules

- **CLI parity is a separate track.** It covers invocation, interactive behavior, commands, providers, configuration, sessions, tools, resources, extensions, automation protocols, SDK integration, and security documented by Pi `1.0.0`.
- **Web scope is delta-only.** It does not recount all Pi Web `0.9.3` behavior. Existing AiHarness equivalents are recorded only as foundations for a behavior added or materially changed in `0.10.0`.
- Similar names do not prove parity. AiHarness's provider, extension, JSONL, RPC, and session APIs are evaluated against Pi's observable contracts.
- A different internal architecture is acceptable for Web behavior. Exact wire, command-line, session-file, and SDK compatibility is required where a Pi CLI integration depends on that contract.
- Each criterion groups one independently closable contract. Annex B maps all changed upstream file families into the Web criteria; individual upstream tests are evidence, not separate criteria.

### Known limitations

- This was primarily a static source, documentation, diff, and test-inspection audit. No Pi or Pi Web server was executed, and no upstream test suite was run.
- The latest implementation re-audit ran Docker TypeScript checks, all 74 Vitest files / 741 tests, all 200 Playwright tests without retry, documentation lint, a production image build, and compiled print/list/RPC/API-key-override smoke tests. Two earlier no-retry Playwright attempts exposed transient Chromium worker `SIGSEGV` failures under Docker's former 64 MiB shared-memory allocation, plus one transient visual mismatch; every affected case passed a focused no-retry rerun, and subsequent complete suites pass with 1 GiB of shared memory. No real-provider credential test, cross-platform terminal matrix, or new visual baseline was run.
- Provider credentials, browser/device OAuth, ambient cloud credentials, real MCP servers, destructive package operations, cross-platform terminals, and OS file managers were not exercised.
- No new screenshots were captured. Every changed Web visual surface remains open, so this report cannot be closed on static inspection alone.
- Upstream clones under `/tmp/audit-pi-mono-1.0.0` and `/tmp/audit-pi-web-0.10.0` were working copies used for inspection. The repository URLs and hashes above are the durable references.
- `docs/audit/pi/.gitignore` contains `*`. Consequently `AUDIT-2.md` is ignored and will require an explicit force-add or an intentional ignore-policy change before normal versioned delivery. This does not change a product criterion's status.
- The absent standalone paths `packages/web/src/components/WorkspacePicker.tsx` and `packages/web/src/components/SkillSettings.tsx` are not treated as requirements: workspace and skill behavior is assessed where it actually lives, principally `Sidebar.tsx` and `SettingsView.tsx`.
- Any target or local implementation evolution requires a new audit or an explicitly journaled re-audit.

## 4. Convention for Future Audits

| State | Meaning |
|---|---|
| `ABSENT` | Required deliverable or compatibility evidence does not exist. |
| `PARTIAL` | A demonstrable foundation exists, but the full criterion is unmet. |
| `TO BE DEFINED` | A product, security, compatibility, or scope decision is required. |
| `IN PROGRESS` | Implementation or verification is actively underway and linked in the journal. |
| `BLOCKED` | An external blocker, owner, and release trigger are documented. |
| `DONE` | The complete criterion is verified at the pinned target with evidence and applicable tests/visuals. |
| `GAP ACCEPTED` | A dated final decision intentionally declines the criterion with justification and a re-examination trigger. |

### Closure Rule

Move an item to `DONE` only after all behavior named in its row is implemented, Pi-compatible contracts or explicit migrations are tested, security-negative paths pass, documentation is updated, applicable desktop/mobile visuals are reviewed, and the journal records commands actually run. `PARTIAL` is never closed. Mark this report `DONE` only when every criterion is `DONE` or `GAP ACCEPTED`.
