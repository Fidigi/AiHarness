**Objective:** determine, at the pinned AiHarness commit, (1) the complete functional and safety gap to Pi CLI `1.0.0`, and (2) every material capability introduced by the pinned Pi Web `0.9.3..0.10.0` delta. Pi is a behavioral reference, not a public interface target: AiHarness owns its names, paths, environment variables, command syntax, wire formats, persisted schemas, extension API, and SDK.

### Scope rules

- **CLI parity is a separate track.** It covers invocation, interactive behavior, commands, providers, configuration, sessions, tools, resources, extensions, automation, SDK integration, and security documented by Pi `1.0.0`.
- **Web scope is delta-only.** It does not recount all Pi Web `0.9.3` behavior. Existing AiHarness equivalents are recorded only as foundations for a behavior added or materially changed in `0.10.0`.
- Similar names do not prove functional parity, and different names do not disprove it. Provider, extension, JSONL, RPC, session, and SDK behavior is assessed through documented AiHarness-owned interfaces.
- Upstream public compatibility is out of scope. No criterion requires upstream names, directories, environment variables, command spelling, wire envelopes, persisted formats, source-level extension loading, package imports, or drop-in SDK substitution.
- Each criterion groups one independently closable capability. Annex B maps all changed upstream file families into the Web criteria; individual upstream tests are behavioral evidence, not separate criteria.

## 4. Convention for Future Audits

| State | Meaning |
|---|---|
| `ABSENT` | Required functional deliverable or evidence does not exist. |
| `PARTIAL` | A demonstrable foundation exists, but the full criterion is unmet. |
| `TO BE DEFINED` | A product, security, or scope decision is required. |
| `IN PROGRESS` | Implementation or verification is actively underway and linked in the journal. |
| `BLOCKED` | An external blocker, owner, and release trigger are documented. |
| `DONE` | The complete criterion is verified at the pinned target with evidence and applicable tests/visuals. |
| `GAP ACCEPTED` | A dated final decision intentionally declines the criterion with justification and a re-examination trigger. |

### Closure Rule

Move an item to `DONE` only after all behavior named in its row is implemented through documented AiHarness contracts, relevant state migrations are tested, security-negative paths pass, documentation is updated, applicable desktop/mobile visuals are reviewed, and the journal records commands actually run. `PARTIAL` is never closed. Mark this report `DONE` only when every criterion is `DONE` or `GAP ACCEPTED`.
