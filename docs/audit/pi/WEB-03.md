# WEB-03 — Native Settings administration contract

Scope: Pi 1.2.0 / Pi Web 0.12.2 comparison in [AUDIT-5](./AUDIT-5.md), criterion WEB-03. This is the native browser administration contract, not foreign-file compatibility, upstream-account qualification, or closure of MOD/MCP/WEB-06.

## Control, storage and authority map

`data` below means the server's configured data directory, not the browser's home. A project identifier is the canonical workspace ID; a scope selector is never a filesystem path or a trust grant.

| Settings control | Storage and scope | Read/write contract and limits |
|---|---|---|
| Server Bearer token / sign out | Explicit token in per-tab `sessionStorage`; login uses opaque HttpOnly server cookie | `setAuthToken`, `/api/auth/*`; not a provider credential. Sign out clears local token and server Web session. No durable localStorage token |
| Active provider/model | Web selection state and bounded session-view cache; run/session overrides are explicit | Selection is not a write to global defaults or a credential grant. Catalogue availability and enabled state are distinct |
| Built-in provider key | Encrypted server credential ownership when a master key is present | `POST /api/config`; credentials capability; refuse missing durable encrypted storage. Password input masks after success, never read back a key |
| Provider lifecycle: status, Connect, Cancel, Disconnect, Test | Server encrypted credentials and process-local expiring OAuth flows; global | `/api/provider-registry/auth*`, OAuth and Test routes. Status is not a quota, login, discovery or generation request; explicit Test/login may contact upstream |
| Custom provider create/edit/delete, URL/dialect/headers/key | Non-secret declarations in `data/providers.json`; credentials in `provider-secrets.enc`; global | `/api/provider-registry/custom`; credentials capability. Empty key means retain existing key, not reveal it. Native validation/collisions apply; rename remains separately capability/revision-gated and off on ordinary shared hosts |
| Import models / custom model CRUD, capabilities, limits, prices, compatibility, Test | Global declarations in `data/providers.json`; actual adapter metadata/discovery remains separate | `/api/provider-registry/custom/:id/import-models`, `/models`; explicit Test is not merely form validation. Import preserves operator rows. Static-only adapters can import known declarations but refuse network discovery Test with 409 |
| Defaults: provider, model, thinking, numeric budgets, preset | `data/config.json` global/project layers | `/api/configuration/scope` PATCH changes dirty keys only; empty means `null` removal/inherit. | Models: individual/provider/displayed activation | `enabledModels` in global config, or selected project config when a workspace exists | `/api/models/enabled/batch`; at most 500 exact changed qualified keys, not names/globs. | Plugins: source/scope Install, row activation/remove, group activation, Check/Update, Reload | Private `data/plugins.json` and managed package tree; global/project scoped ownership | `/api/plugins*`; packages capability plus fresh source/project trust. Group activation targets only changed **displayed** packages in that scope. Check/Update/Install/Reload are explicit; passive catalogue reads do not execute npm/Git/modules. Executable activation may need explicit reload; a persisted package switch is not proof that code reloaded |
| MCP import/replace, row/group activation, exposure, Remove/Undo, Test, OAuth | Global `data/mcp.json`, trusted project `.ai-harness/mcp.json`; encrypted server OAuth credentials; process-local Test/runtime/undo/flow state | `/api/mcp*`; file revision/config key, fresh trust and capabilities. Preview is redacted and passive; original text is reparsed on write. Test/OAuth are explicit operations, not inventory side effects; no browser transport secrets |
| Subagent settings/profile controls | Native global/project `data/subagents.json` ownership | `/api/subagents/settings|profiles`; not Pi profile-file compatibility or WEB-06 runtime/delegation qualification |
| Appearance, language, send mode, size/width, disclosures, sound/notifications, selection actions, shortcuts | Validated browser preferences v4/local locale key | Browser-local, not server defaults. ## Unsupported and intentionally distinct cases

- Pi Web's provider quota/remaining allowance/reset summaries have **no native equivalent**. Native `usage-metrics.json` contains historical observed requests/tokens/cost, not an issuer quota, balance or subscription entitlement. Catalogue prices may be unknown; the compact historical counters are not a completeness certificate or a quota/balance estimate.
- Pi `models.json`, settings/auth files and extension ABI are not edited, imported or synchronized. Native configuration and encrypted credential stores remain separate. Browser administration does not supply every operator-owned agent-file field or filesystem editor.
- Built-in/custom connection, OAuth/subscription, live discovery, classifier/image and adapter support are exactly those exposed by the native provider implementation. A row, import, configured flag or local fixture is not vendor-account or full catalogue qualification. MOD-01 remains independent.
- Environment-owned credentials/settings cannot be removed by a lower-scope save. Disconnection is local deletion, not issuer-side revocation. Unsupported OAuth/discovery operations must refuse; do not substitute chat, silently change dialect, or invent a successful Test.
- Native MCP import/exposure/OAuth/file controls do not imply Pi wire/file compatibility or completion of all MCP runtime/resource features. Security capability/Origin/trust guards remain unchanged.

## Save, failure and retirement rules

1. Treat the server as canonical. Patch only changed keys; preserve sibling fields and unselected scopes. Null removes a stored default, not its inherited source.
2. Defaults reread both the saved scope and effective provenance after **every** mutation response, including transport errors. Successful readback replaces the form with saved values; a failed response is still reported as unconfirmed, never silently called success. This may discard an attempted draft in favor of canonical values; it does not undo an admitted write.
3. If either read fails, withdraw effective provenance, disable further default writes, show fixed EN/FR feedback and offer **Reload saved settings**. Do not echo server exception bodies into that feedback. Explicit reload discards the attempted form and rereads canonical values.
4. Package mutation/reload failure also rereads the canonical inventory, never restores an optimistic pre-write catalogue. Failed readback hides stale package controls and blocks Install/Reload until an explicit catalogue refresh succeeds. Preserve a conservative pending-reload warning; do not claim executable rollback.
5. Epoch guards retire default/package operation publication and notices on scope/workspace/unmount replacement. They do not cancel a write already accepted by the server. Existing model/skill batch and MCP owners separately preserve view/generation and revision-bound publication.
6. Generic config defaults are dirty-key, fresh-merge writes, **not** a whole-form compare-and-swap transaction. Concurrent writes to the same key are last admitted writer wins. MCP/provider rename have their own explicit stale-revision refusals; do not invent a global revision protocol.
7. Use associated labels, native keyboard controls, disabled states and live status/alerts. Keep user data inert. Existing typed MCP/batch/provider diagnostics remain localized; server-owned technical diagnostics are not translated by parsing arbitrary English exception text.
